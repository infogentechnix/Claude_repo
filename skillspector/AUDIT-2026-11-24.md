# SkillSpector audit of installed repos — 2026-11-24

Static scan (`skillspector scan <dir> --no-llm`, SkillSpector 2.13.7) of every skill, agent, command,
hook and script already installed in this repo, run before the install gate existed. LLM analysis was
not run. Re-run any target with `bash skillspector/scan.sh <path>`.

## Result

**361 targets scanned: 258 SAFE, 67 CAUTION, 36 DO_NOT_INSTALL.** `.claude/gsd-core/bin` (the GSD CLI, 14 MB tree) was still scanning when this was written; its other four folders are included.

No malicious behaviour was found. Every CRITICAL finding and every rare HIGH pattern was read in source,
and the common HIGH patterns were sampled. The DO_NOT_INSTALL verdicts are driven by text matches that
SkillSpector's static rules cannot tell apart from intent. One skill had real (non-malicious) security
weaknesses, which were fixed (below).

## Fixed: `meta-ad-builder` (Arcads)

The CRITICAL `TT3` taint flows (environment → network) in `arcads/shared/skills/meta-ad-builder/scripts/`
pointed at real weaknesses in how the Meta Graph API was called:

| Issue | Fix |
|---|---|
| Access token sent as a URL query parameter on GETs (`?access_token=…`), where proxies, server logs and error messages record it; `check-meta-env.sh` also put it in the curl URL, visible in `ps` | Token sent only as `Authorization: Bearer` (`meta_api.auth_headers()`); the shell check passes the header on stdin |
| `paging.next` URLs from API responses were followed with the token, whatever host they named | `meta_api.is_graph_url()`: pagination stops unless the link is `https://graph.facebook.com` |
| `META_API_VERSION`, ad account ID, `video_id`, `ad_id`, `adset_id`, `page_id` and a user-typed page name went into the URL path unchecked (`me/adaccounts`, `..`, `?x=` could retarget the call) | `meta_api.graph_url()` validates every path segment; IDs must be numeric / `act_<digits>`; API version must match `vNN.N` |
| Three requests had no timeout; 429/5xx retries in `pull-competitor-ads.py` were unbounded and `int(Retry-After)` crashed on a non-numeric header | Timeouts on every call; at most 5 retries; `Retry-After` capped at 300 s and parsed safely |

`tests/test_meta_api.py` (11 tests) covers each fix; the tests fail against the original code and pass
now. The five `TT3` findings still appear on rescan: SkillSpector cannot see the validation in
`graph_url()`, and an API client necessarily sends its key. They are reviewed and accepted.

## Reviewed and accepted (false positives)

| Pattern (rule) | What it actually matched |
|---|---|
| Tainted flow env → network (`TT3`, CRITICAL) | Arcads image skills and `import_ads.py` sending their own API key to their own vendor: `external-api.arcads.ai`, `graph.facebook.com`, `api.airtable.com`. `import_ads.py` already used Bearer headers, redacted errors and numeric-ID checks |
| Credential access (`PE3`, 148 hits) | Mentions of `.env`, "access token", Keychain; in ECC/GSD hooks, deny-lists that *block* `id_rsa`, `.netrc`, `.env.local`; `/etc/passwd` in GSD comments explaining a path-traversal fix |
| Tool parameter abuse (`TM1`) | Guard hooks and docs quoting `rm -rf /`, `git push --force`, `git reset --hard` in order to block them; GSD `sync-skills` `rm -rf "$DEST_ROOT/$SKILL"` runs only after an empty-root guard; `--no-safe-zone` is an image-layout flag |
| Instruction override / hidden instructions / prompt extraction (`P1`, `P2`, `P6`, `YR4`) | Anti-injection guidance ("ignore previous instructions" quoted as an example to refuse); HTML-comment placeholders in GSD templates |
| Anti-refusal (`AR1`–`AR3`) | Ordinary wording: "no warnings", "do not judge", Perl's `no warnings` |
| Agent config access (`AS1`, `AS2`) | Skills whose stated job is reading `~/.claude/settings.json` or MCP config (`ck`, `config-gc`, `skill-scout`, `security-scan`) |
| External script fetching / remote bootstrap (`SC2`, `YR1`) | `curl` calls to the Arcads API; install docs (`npm install -g postiz`); test fixtures that list malicious commands to assert they are blocked |
| Memory manipulation (`MP3`) | Code that resets its own state files |
| Incomplete analysis (`AE1`) | The scanner could not fully parse a referenced file; a coverage note, not a finding |

Notes: `.claude/skills/postiz` is a symlink, which SkillSpector refuses to follow, so its target
`.agents/skills/postiz` was scanned. The ECC library (299 skills, 68 agents, 98 commands) is not loaded
by default.
